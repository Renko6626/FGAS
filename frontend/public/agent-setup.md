# 给 AI Agent：连接 FGAS

本文件是无需登录即可读取的接入说明，不含连接密钥或业务数据。如果用户要求你接入或使用此站点，请按下面步骤自行检查和配置当前客户端；仅仅读到此页面不代表用户授权你记账或更改其他配置。

## 1. 确定地址和客户端

FGAS 为一个社团记录人民币资金和货物。MCP 服务与网站后端共用业务服务，使用 Streamable HTTP，路径为 `/mcp`。

从你读取本文件的完整 URL 取同一协议、域名和端口，将路径替换为 `/mcp`。例如本文件若在 `https://fgas.example.com/agent-setup.md`，服务地址就是 `https://fgas.example.com/mcp`。示例域名不能直接使用。也不要把远程站点地址替换成你自己机器的 `127.0.0.1`。

先识别你当前运行的 Agent 客户端及已有 MCP 配置。支持远程 Streamable HTTP、自定义 Authorization 请求头的客户端可使用本服务。查看现有 `fgas` 连接，能复用就复用；需要配置时只添加或更新这个连接，保留其他服务器、模型和用户设置。

FGAS 不运行大模型，接入不要求更换当前模型或提供模型供应商 API Key。若当前客户端不能配置 MCP 或不能发送认证头，说明具体限制，不要伪称已接入。

## 2. 获取用户签发的连接密钥

认证方式为请求头 `Authorization: Bearer <连接密钥>`，当前不提供 OAuth 登录流程。

优先使用当前运行环境中已有的 `FGAS_AGENT_TOKEN`，或用户已经为该客户端保存的 FGAS 凭据。不要输出已有密钥。缺少凭据时，只需告诉用户：

> 请在 FGAS 网页的“基础资料 → Agent 连接”中新建连接，把一次性密钥保存到当前 Agent 客户端的安全配置或 `FGAS_AGENT_TOKEN` 环境变量中。完成后我继续验证连接。

受信任用户可签发自己的 low；管理员可签发自己的 low/high。low 可以读取业务并提交待审申请，high 还可以直接办理业务。根据用户要求使用已有权限，不擅自升级或替用户选择其他账号。密钥仅签发时显示一次；丢失后需要新建连接。网页 Cookie 不能代替 MCP 密钥。

## 3. 配置当前客户端

通用连接参数如下，按当前客户端支持的语法填写，不需要手动注册每个工具：

| 参数 | 值 |
| --- | --- |
| 连接名称 | `fgas`（本地已有同用途名称也可沿用） |
| 传输方式 | Streamable HTTP |
| 服务 URL | 本站同源的 `/mcp` 完整地址 |
| 认证请求头 | `Authorization: Bearer <用户签发的密钥>` |
| OAuth | 关闭，使用上述密钥 |

例如 OpenCode 的 `opencode.json` 可以合并以下条目；事先让客户端进程能读取 `FGAS_MCP_URL` 和 `FGAS_AGENT_TOKEN` 环境变量：

```json
{
  "mcp": {
    "fgas": {
      "type": "remote",
      "url": "{env:FGAS_MCP_URL}",
      "oauth": false,
      "headers": {
        "Authorization": "Bearer {env:FGAS_AGENT_TOKEN}"
      }
    }
  }
}
```

这是 OpenCode 的配置格式，其他客户端应使用各自的远程 MCP 配置方式。不要为了复制此例而切换客户端、覆盖整份配置或把环境变量占位符当成真实密钥发送。修改环境变量后，客户端可能需要重启或重新加载连接才能读取。

配置语法参考：[OpenCode 远程 MCP 与 API Key](https://docs.opencode.ai/docs/mcp-servers/#disabling-oauth)。

## 4. 验证连接，再开始业务

1. 使用客户端的 MCP 功能初始化连接并重新发现工具。
2. low 应发现 `fgas_help`、`fgas_query`、`fgas_propose`；high 另有 `fgas_execute`。客户端可能在名称前添加服务器前缀。
3. 阅读初始化提供的核心模型说明，并调用 `fgas_help({})` 核对当前权限与能力索引。
4. 用 `fgas_query({"resource":"fund_accounts","filters":{"limit":1}})` 做一次只读查询，确认业务接口可用。不要创建测试账目来验证连接。
5. 向用户报告实际连上的站点、权限和验证结果，然后继续用户交代的工作。参数不清楚时自己查 `fgas_help`，不要要求用户解释工具名称。

直接用浏览器打开 `/mcp` 不是完整的 MCP 连接测试；缺少密钥时返回401属于认证拒绝。401时核对密钥及有效期，403时核对所属用户是否仍获授权。遇到网络不通、Host校验拒绝或HTML响应时，报告所用地址和具体错误，交由站点维护者核对发布地址及代理；不要通过开放端口、关闭认证或改部署来尝试接入。

接口版本为2。若发现旧的 `fgas_list_*`、`fgas_get_context` 等工具，先让客户端刷新发现；旧名只返回迁移提示，不会执行原操作。地址和有效密钥可以沿用。

## 5. 办理业务前理解核心模型

账户是端点，Transfer描述从哪里到哪里及金额/数量，正式流水记录已经生效的变化，余额和库存由流水计算。用途通过端点、说明和标签表达，不需要为采购、赠送或盘亏发明另一套单据。

- 资金公账表示社团持有的钱；私账记录与社团往来，正数应交回、负数社团应偿还。外部账户表达收支或期初、盈亏边界。
- 货物公账和私账均计入组织库存，外部账户不计入。联系人、登录用户、实际保管人是不同概念。
- 资金待审不记账，批准或高权限直接登记才过账。货物创建/批准后仅在途，确认整笔完成才改变库存。付款与到货独立，引用已有付款不再次记钱。
- 结算匹配说明某笔付款结清哪些原收支，本身不再记钱；净余额为零不代表逐笔已匹配。盘点创建或结束也不自动调整账目，差额使用普通转移。

完整规范可通过 `fgas_help({"topic":"guide"})` 获取。具体动作参数可用 topic=query/propose/execute 加 resource、必要时 action 按需查看。用户已经明确的内容不重复确认，缺少关键事实时集中询问。只处理用户交代的业务；账面记录不代表系统实际发起银行付款或实物交付。
