# 给 AI Agent：连接 FGAS

这份指南不用登录就能看，里面没有密钥或业务数据。用户让你接入 FGAS 时，可以照着下面的步骤检查并配置当前客户端。读到这份指南本身，不代表用户让你开始记账或修改其他设置。

## 1. 确定地址和客户端

FGAS 用来记录一个社团的人民币资金和货物。MCP 和网页调用的是同一套业务功能，连接方式是 Streamable HTTP，地址路径为 `/mcp`。

找到你正在读取这份文档的网址，保留协议、域名和端口，把路径换成 `/mcp` 就是连接地址。例如，文档地址是 `https://fgas.example.com/agent-setup.md`，MCP 地址就是 `https://fgas.example.com/mcp`。配置时要换成实际网址，不能直接用这个示例。远程网站也不能填成 `127.0.0.1`，那会连到你自己所在的机器。

先看自己运行在哪个 Agent 客户端里，再检查它现有的 MCP 配置。客户端需要支持远程 Streamable HTTP，并且能发送自定义的 Authorization 请求头。如果已经有 `fgas` 连接，就先尝试使用；需要修改时，只改这一项，保留其他服务器、模型和用户设置。

FGAS 自己不运行大模型，连接它不需要换模型，也不需要另外提供模型供应商的 API Key。如果当前客户端不支持配置 MCP，或不能发送认证头，就把这个限制告诉用户，不能说已经连好了。

## 2. 获取用户签发的连接密钥

连接时要在请求头里带上 `Authorization: Bearer <连接密钥>`。目前使用密钥认证，没有 OAuth 登录流程。

先看看运行环境里有没有 `FGAS_AGENT_TOKEN`，或者客户端是否已经保存了 FGAS 的密钥。有的话直接使用，不要把密钥打印出来。没有的话，告诉用户这一步就够了：

> 请打开 FGAS 网页，在“基础资料 → Agent 连接”里新建一个连接。把页面显示的密钥存到当前 Agent 客户端的安全配置，或 `FGAS_AGENT_TOKEN` 环境变量里。存好后，我继续检查能不能连上。

受信任用户可以创建自己的 low 连接；管理员可以创建自己的 low 或 high 连接。low 能查数据、提交待审申请，high 还可以直接办理业务。按用户的要求使用现有权限，不要自行升级权限或换账号。密钥只在创建时显示一次，丢失后需要新建连接；网页登录用的 Cookie 不能拿来代替它。

## 3. 配置当前客户端

连接需要填写的信息如下。按当前客户端的格式配置即可，不用逐个添加工具：

| 参数 | 值 |
| --- | --- |
| 连接名称 | `fgas`（本地已有同用途名称也可沿用） |
| 传输方式 | Streamable HTTP |
| 服务 URL | 本站同源的 `/mcp` 完整地址 |
| 认证请求头 | `Authorization: Bearer <用户签发的密钥>` |
| OAuth | 关闭，使用上述密钥 |

以 OpenCode 为例，可以把下面这一项加入已有的 `opencode.json`。使用前，先确保客户端进程能读到 `FGAS_MCP_URL` 和 `FGAS_AGENT_TOKEN` 这两个环境变量：

```json
{
  "mcp": {
    "fgas": {
      "type": "remote",
      "url": "{env:FGAS_MCP_URL}",
      "oauth": false,
      "headers": {
        "Authorization": "Bearer {env:FGAS_AGENT_TOKEN}"
      }
    }
  }
}
```

其他客户端的配置格式可能不同，用它自己的远程 MCP 配置方式就行，不必换成 OpenCode。添加时保留原有配置，也别把示例中的环境变量占位符当作密钥发出去。环境变量改好后，可能需要重启客户端或重新加载连接才会生效。

配置格式可以查阅：[OpenCode 远程 MCP 与 API Key](https://docs.opencode.ai/docs/mcp-servers/#disabling-oauth)。

## 4. 验证连接，再开始业务

1. 在客户端里连接 MCP，让它重新读取服务器提供的工具。
2. low 应能看到 `fgas_help`、`fgas_query`、`fgas_propose`；high 还会多一个 `fgas_execute`。有些客户端会在工具名前加上服务器名称。
3. 先读连接时返回的核心模型说明，再调用 `fgas_help({})`，看看当前是什么权限、能做哪些事。
4. 调用 `fgas_query({"resource":"fund_accounts","filters":{"limit":1}})`，查一条资金账户来确认接口可用。查数据就够了，不用新建测试账目。
5. 告诉用户连上了哪个站点、有什么权限、检查结果如何，然后继续处理用户交代的事。遇到不熟悉的参数，自己查 `fgas_help`，不用让用户解释工具名称。

只在浏览器里打开 `/mcp`，还不能判断 MCP 是否连接成功。没有带密钥时，返回 401 表示认证没有通过。遇到 401，检查密钥和有效期；遇到 403，检查连接所属用户是否还有相应权限。

如果连不上网络、域名被 Host 校验拒绝，或者收到的是 HTML 页面，就把使用的地址和具体错误告诉站点维护者，请其检查网站对外使用的地址和代理设置。不要为了连通而自行开放端口、关闭认证或改动部署。

当前接口版本是 2。如果客户端还显示旧的 `fgas_list_*`、`fgas_get_context` 等工具，让它刷新工具列表。旧工具名只会返回迁移提示，不会执行操作；原来的地址和仍然有效的密钥可以继续使用。

## 5. 办理业务前理解核心模型

账户表示钱或货物的来源和去向。Transfer 是一笔转移，记录从哪里到哪里、转了多少钱或多少货物。转移生效后才生成正式流水，余额和库存都根据这些流水计算。采购、赠送、盘亏等用途，可以用来源和去向、说明、标签来表达，不必另造一套单据。

- 资金公账记录社团持有的钱；私账记录与社团之间的往来。私账余额为正，表示应向社团交回；为负，表示社团应偿还。外部账户用来表示对外收支、期初和盈亏。
- 货物公账和私账里的货物都算组织库存，外部账户里的不算。联系人、登录用户和实际保管人要分清，不能当作同一个身份。
- 资金申请还在待审时不记账，批准或高权限直接登记后才过账。货物创建或批准后只是“在途”，确认整笔完成后才改变库存。付了钱不代表货已到；引用已有付款时，也不能再记一笔相同的付款。
- 结算匹配用来说明一笔付款结清了哪些原收支，匹配本身不再记钱。私账余额为零，也不代表每笔收支都已经匹配。创建或结束盘点不会自动调账，盘点差额仍要用普通转移记录。

需要完整说明时，调用 `fgas_help({"topic":"guide"})`。查某个动作的参数，用 topic=query/propose/execute 加 resource；执行动作还需要 action。用户已经说清楚的内容不用再确认，有关键事实没说清时，把需要补充的问题一起问出来。只办理用户交代的事；在这里记账，不代表系统已经发起银行付款或完成实物交付。
