# 网页助手

设计见 [接入设计](superpowers/specs/2026-10-28-web-agent-design.md)，完整分期和实施记录见 [实施计划](superpowers/plans/2026-10-28-web-agent-prototype.md)。2026-10-29 已合并到主目录 `main` 并经既有 Actions → ACR → Coolify 发布至 [FGAS](https://fgas.secret-sealing.club)；发布代码为 `f1bc6aa`，数据库已备份后升级到 `0002`。保留当前页面内存会话等原型边界，未做真实模型验收。交付见 [云端发布记录](superpowers/plans/2026-10-29-web-agent-cloud-release.md)。

## 已有能力

- 工作台右下角“网页助手”随时打开独立悬浮组件，切换业务页面或收起面板均保留会话、个人 Key 和正在接收的回复。桌面面板宽 560px，标题、工具栏和输入区缩减留白，主要区域用于聊天记录。模型配置位于独立弹窗，只有手动打开设置、无可用配置时尝试对话，或模型配置报错时才弹出。关闭错误弹窗后再次发送会先引导配置；修改或明确确认配置后再由用户发送。未执行工具、未收到回复时，失败请求的输入回到输入框；已有工具结果保留。桌面和手机沿用现有样式。
- 后端 Pydantic AI 运行多步工具循环，使用本人启用且未过期的连接，MCP 保持 Bearer 认证。普通用户仅 low；受信任用户和管理员可选择本人 low/high。low 查询及提交待审申请，high 还可在明确确认具体操作后直接办理。propose 对两档均保持待审。
- 个人 DeepSeek Key 或管理员提供的公共模型，官方 Chat Completions 接口；支持 `deepseek-flash`、`deepseek-v4-pro`。
- 助手回复支持基础 Markdown：标题、列表、粗体、引用、代码块、链接和表格。原始 HTML 按文本显示，图片不加载；用户输入仍显示纯文本。FT/ST 编号可以打开现有详情，使用页内链接维持助手连接。
- 每轮工具进度收在对应回复顶部，默认折叠，不另占聊天底部；已返回不等于业务成功。中断的回复标记“本轮未完成”，未返回的工具显示“待核对”，业务是否已提交以记录为准。本页会话 token 用量以小字保留。
- 桌面悬浮窗口默认宽 560px，可展开到 860px；手机使用全高窗口。正文字号保持 13px。用户上翻阅读时停止自动跟随，并可点“回到最新”；发送新消息时定位新的回复。空会话只显示一句简短引导。
- 管理员可以查询公共 DeepSeek 账户余额。原型展示的是本页会话 token，不是全站历史消费账单，也不估算扣款。
- 原型开启时，Casdoor 首次建立用户会同步创建启用的 low“网页助手”；已有用户可以选择本人连接或创建一个。停用连接不会自动重建。
- 连接管理页面允许受信任用户和管理员签发或升级本人的 high；聊天工具栏和模型设置均可选择已有连接，列表标明等级，展开时刷新。默认选择 low，只有 high 可选时也等待手动选择；运行中禁止切换，切换不清空原生历史。high 执行写入后刷新工作台资料。

## 启动

以下命令在项目主目录执行。独立虚拟环境避免更新日常开发环境的 Starlette/OpenAI SDK：

```bash
python3.13 -m venv .runtime/web-agent-venv
.runtime/web-agent-venv/bin/python -m pip install -r backend/requirements-agent.txt
.runtime/web-agent-venv/bin/python scripts/run-web-agent-prototype.py
```

启动器默认使用主工作区 `.runtime` PostgreSQL socket、55438 端口上的 `fgas_test`；可通过 `DATABASE_URL` 指定同名专用测试库，启动器会检查实际库名并拒绝其他库。它不清库、不执行迁移、不初始化种子；需要已准备好的当前测试库。开发账号为既有 `admin`、`trusted`、`untrusted`。不要把它指向日常 `fgas`。

另开终端启动前端：

```bash
cd frontend
VITE_API_PROXY_TARGET=http://127.0.0.1:10632 npm run dev -- --host 127.0.0.1 --port 5186 --strictPort
```

本轮已运行的后端为 `http://127.0.0.1:10632`，前端为 `http://127.0.0.1:5186/?assistant=1`。先选择开发账号登录；`assistant=1` 会自动展开面板，仅用于方便预览。开发环境会话可以从“当前账号”切换。

本轮隔离虚拟环境实际路径 `/tmp/sunyunbo/fgas-web-agent-venv`；重新启动可用其中的 Python。换机器后按上面的命令重新创建即可。

## 模型 Key

个人 Key 填入面板“模型设置”，只保存在当前页面内存，通过 Cookie HTTP 请求交给后端调用，不放入 MCP 工具参数。管理员可在“基础资料 → 公共模型设置”保存、替换、清除公共 DeepSeek Key，并主动查询公共账户余额。成员在助手模型设置中选择“社团提供的 DeepSeek”使用公共模型。

2026-10-29 用户确认采用简单的数据库明文方案：Key 保存在 `web_agent_settings` 单行配置中，数据库备份也包含明文；页面和 HTTP 响应不回传 Key，只有管理员的 Cookie 会话可管理。保存后新的聊天和余额请求立即使用，不改变已开始的请求。数据库配置优先；没有数据库配置时，仍使用环境变量 `FGAS_DEEPSEEK_API_KEY`。清除网页配置后若环境变量存在，页面明确标注继续使用服务器配置。环境变量变更仍须重启后端；启动器可从当前项目 `.env` 读取这一项。其他系统的认证 Key 不用于模型调用。

新增表使用 Alembic `0002`，保留 `0001` 基线；启用新版前先备份，再执行 `alembic upgrade head`。开发时先升级专用 `fgas_test`，2026-10-29 云端发布再经迁移前备份升级生产库，日常本地库未改。公共设置仅在网页助手启用时提供，MCP 不提供模型 Key 管理。

没有个人 Key 时可以使用已配置的公共模型。个人模型报错时由用户主动切换来源，程序不自动切换并重播业务工具。不要把真实 Key 提交到 Git。直接运行后端时仍默认关闭；发布镜像安装 `backend/requirements-agent.txt`，Coolify Compose 默认开启助手，并将 MCP 地址设为容器内的 `http://127.0.0.1:10622/mcp`。独立手动 Compose 保持可选开启。

## 助手提示词

每轮模型请求由 `backend/application/web_agent.py` 读取并组合两份文档：

- [web-agent.md](ai/web-agent.md)：网页助手提示词初稿，定义身份、语气、任务推进、工具使用、授权与隐私限制、结果和异常表达，并给出少量示例。
- 提示词单独解释 `fgas_help/query/propose/execute` 的职责、两档连接的范围及按资源查询帮助的方式；通用 `filters/data` 不能作为自由字段使用。已有完整契约可沿用，缺少实际参数说明时先查具体帮助。
- [overview.md](ai/overview.md)：与外部 MCP Agent 共用的账本模型、业务生效规则和调用约定。具体参数和完整业务指南仍由 `fgas_help` 按需提供。

前者仅供网页助手，不改变外部 MCP 的说明。当前未注入用户所处页面、选中单据等上下文；提示词要求助手如实说明能力，不假装能看见或操控页面。网页提示词每轮读取，修改后下次发送即可使用；外部 MCP 的初始化说明和帮助文档在服务启动时加载，修改共用 overview 或 guide 后需重启后端，使两条入口一致。这不等于真实模型已经验收。

每轮另提供上海时区（UTC+08:00）的当前时间，用于换算用户明确说出的相对日期；不替缺失的业务日期作决定。单轮仍最多 10 次模型请求，提示词要求最多调用工具 8 次并预留答复；较长任务分批报告覆盖范围和接续位置，不重复已成功写入。

服务端每轮补充当前实际连接等级，聊天界面也按开始事件核实等级。网页助手提示词、共用 MCP 核心说明、完整指南及 execute 工具说明均要求：先说明对象、动作、关键参数和直接生效影响，得到用户明确确认后才能 execute；同一已确认批次不逐个重复询问。切换 high 不算确认。这是提示词行为约定，没有新增后端确认令牌或审批状态机；原有服务端授权和账本校验继续执行。

跨轮保留 Pydantic AI 原生完整消息，包含工具调用 ID、参数、结果和框架记录的其他消息部分。后端在 SSE `history` 事件中返回，前端独立存放在当前页面内存，下轮原样回传；聊天展示不参与重建模型历史。服务端通过原生适配器解析，并用框架默认清理函数移除客户端指令等内容，系统提示词仍由服务端提供。历史仅用于上下文，不扩大权限或替代当前业务状态核实。

普通报错前已捕获的消息也随历史返回；主动停止、断线时未返回的记录不做恢复。清空会话会同时清空聊天展示和原生历史，刷新或退出仍清空。此次接口不兼容旧文本历史，升级本地预览后需刷新并重新开始对话；未新增数据库或后端会话存储。

工具报错也是 Agent 循环的输入：MCP 已返回的业务错误作为失败结果交给模型；工具参数格式校验提供有限修正预算（2 次），整轮仍最多 10 次模型请求。模型可根据错误查帮助、修正明确未执行的参数或补问用户。权限不足、业务条件不满足不靠换参数绕过；超时或断线导致提交结果未知时仍须先查记录。模型 SDK 的网络自动重试保持关闭。

合并验证：主目录使用独立 Python 环境在专用 `fgas_test` 上运行现有后端检查，85 passed；`npm run build` 与差异检查通过。FunctionModel 替身核对两份文档进入实际模型请求，真实 Cookie/MCP low 身份查询和两轮流式事件完成，未调用供应商。预览已迁回主目录，独立工作树已清理。
