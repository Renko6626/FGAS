# 结算与手机阅读改进

用户在主要页面复查后确认继续实施。沿用已确认的紧凑 ERP 方向，解决结算入口空白、明细事项和金额靠后、手机资料／管理宽表、仓库图缩小难读和助手遮挡。

采用现有 Vue、Naive UI、数据及处理组件，只调整展示与页面内选择，不新增依赖、接口、权限或持久化。不重新建设表格框架；使用一份可选择应用的响应式表格 CSS，原单元格提供字段标签和主次类，桌面仍为原表格，手机改为两列带标签记录。

结算入口根据已有私账账户显示名称、联系人和净余额，支持搜索并进入现有 overview。正负净余额仅说明往来方向，零余额也保留入口，不当作逐笔未结金额或结清判定。进入后保留原选择器、刷新、定位链接、报销／代收／历史和全部匹配信息；事项／日期、金额先于固定三轨账户方向。办理、请求及匹配有效性仍由原服务与 SettlementEditor 负责。

SKU、成员、用户和 Agent 连接沿用单套表格 DOM 与原按钮条件，共用手机标签与布局；优先呈现名称、单位／角色／状态，保留全部资料和已有编辑控件。资金／货物手机行的长账户名换行，并让方向占满主体宽度。

手机仓库使用现有 nodes/routes 显示地点和交接清单，调用原 enter/openRoute；关系图按需展开，桌面和原缩放／拖动、货架保留。手机助手入口收为有明确无障碍名称的图标按钮，聊天操作不变。

取舍：继续纯横向滚动不能解决关键列不可见；为每页新建独立手机组件会重复内容和条件。选用共享 CSS 加原模板标签，避免业务逻辑重复。库存矩阵、CSV 等确实需要宽表的视图继续横向滚动。

验证遵守 AGENTS：前端构建和差异检查，桌面／手机只读截图，包括结算净余额正负零、空入口、长名称、已有角色条件和货架深链接；无自动点击／填表、无新永久测试、无后端全套测试或生产部署。
