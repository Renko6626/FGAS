# 共享手册设计

状态：用户于 2026-11-12 确认单份共享手册、侧边分层章节目录及 MCP 读写（仅 high 可写），随后授权开始实现并更新 AI 提示词。本地实现与验证记录见同日实施计划及阶段记录，尚未发布。

## 目的与方案选择

为社团保存和维护发票流程、储藏室位置、使用规章等长期资料。所有启用中的登录用户可读，受信任用户和管理员可编辑，首页可直接阅读。有效 MCP low/high 连接均可读，仅有效 high 连接可写。

比较过单份共享 Markdown 手册与多篇独立文档：单份手册维护简单，适合当前少量长期资料；多篇文档便于分别管理，但需要额外的文档列表和创建、删除入口。用户选择单份共享手册，使用标题组织章节。

## 阅读与章节目录

- 首页增加“社团手册”区域，显示最后修改人、修改时间、正文预览和展开入口。展开后在首页阅读完整正文，也提供较宽的完整阅读视图；两处使用同一阅读组件及同一份数据。
- 桌面展开阅读时，正文右侧显示独立的章节目录，位于手册阅读区内，沿用现有业务导航。目录在手册范围内随滚动保持可见，目录过长时自身可滚动。
- 从 Markdown 的一级至六级标题自动生成目录，按标题层级缩进，包含子章节；文档标题单独展示，不作为正文中的额外目录项。标题跳级时挂到最近的上级标题下，不要求作者补齐层级。
- 点击目录项滚动定位到对应标题，预留顶部遮挡空间；阅读时标记当前章节。各标题的定位标识在本次渲染中唯一，重复标题也能分别定位。
- 目录定位在组件内部完成，不占用现有用于业务页面导航的 URL hash。第一版不提供跨页面的章节分享地址。
- 手机将侧边目录收为正文顶部的“目录”按钮，展开后仍展示相同的分层结构；选中章节后收起目录并定位正文。
- 没有标题时正常显示正文，并提示可用 Markdown 标题组织章节。

## 编辑与权限

- 受信任用户和管理员可从手册阅读区域打开编辑界面；普通用户只有阅读入口。
- 编辑界面提供标题、Markdown 正文输入、预览、保存和取消；预览与正式阅读使用同一渲染逻辑。
- 手动保存成功后更新阅读内容。保存失败时保留当前输入，显示错误，允许人工重试；取消放弃当前编辑。
- 沿用现有 Cookie 会话与应用层写入授权，每次保存校验账号启用状态及 trusted/admin 角色。
- 多人低频维护按最后一次成功保存的内容生效，不增加版本冲突处理或协同编辑机制。

## 存储、接口与职责

- 沿用 PostgreSQL、SQLAlchemy 和 Alembic，新增 `handbook` 表，只存一份当前手册：固定主键、标题、Markdown 正文、最后修改用户、最后修改时间。通过新 revision `0004` 演进，不修改已有基线。
- 建议人工接口为 `GET /api/handbook` 与 `PUT /api/handbook`。首次保存前返回空正文及默认标题，不在读取请求中创建记录。
- `backend/application/handbook.py` 负责手册查询、保存和写权限，持久化代码遵循已有 infrastructure 模式，HTTP 层仅做身份解析和输入校验。独立于资金、库存内核和业务流水。
- 前端使用独立手册区域、阅读组件和编辑组件，首页接入展示；不把手册正文塞入资金库存汇总数据。手册读取失败时在自身区域显示错误，不阻止首页业务统计显示。
- 复用已安装的 `markdown-it`，正文及目录从同一次 Markdown 解析产生。禁止嵌入 HTML，沿用安全链接处理；第一版支持文字、标题、列表、表格、引用、代码块及链接。
- 手册随数据库备份保存，不新增文件存储、外部文档服务或编辑器依赖。

## MCP 读写

- 沿用现有 `/mcp`、Bearer 认证和 MCP v2 四入口，在工具契约中增加 `handbook` 资源，不另建 MCP 地址或独立工具。
- 读取：`fgas_query({"resource":"handbook"})`，low/high 均可用；返回单对象，包含标题、完整 Markdown 正文（`content`）、最后修改人及修改时间，不分页，不返回网页 HTML。
- 写入：`fgas_execute({"resource":"handbook","action":"update","data":{"title":"社团手册","content":"完整 Markdown 正文"}})`，只允许 high。两个字段均必填，整份替换；首次保存也用同一动作，不提供独立的新建、追加或章节修改动作。
- 写入适配层先调用现有 `require_high`，再复用与网页相同的手册应用服务。每次调用沿用现有连接有效性及所属用户角色检查；即使 low 归管理员所有，仍不可写。最后修改人记录连接所属的真实用户。
- 写入结果沿用现有执行结果封装，明确保存成功、无需审批、不产生资金或库存流水，并返回保存后的手册。网页随后读取到同一份内容。
- low 不提供手册待审提议；需要修改时可生成建议文本，交由有权限的人在网页保存，或由用户授权的 high 连接执行。
- 手册纳入 `fgas_help` 资源发现、精确输入/输出 Schema 和示例；帮助按单对象查询描述，避免沿用分页列表说明。更新共用 Agent 概览、完整指南及网页助手说明，遇到社团流程或规章问题时按需查询最新手册。
- AI 修改前应先读取现有手册，按用户授权的范围调整，并沿用现有 execute 明确确认约定；同一具体修改已确认后不重复询问。手册正文属于业务资料，不能覆盖系统规则、权限限制或替代用户的操作授权。

## 本轮范围

实现单份手册、首页阅读、分层目录、编辑预览及保存，以及 MCP low/high 读取、仅 high 写入。历史版本、回滚、独立草稿、自动保存、图片上传和文档分类不纳入本轮。具体默认标题、排版尺寸和组件拆分由实现时按现有界面处理。

## 验证

- 复用现有真实 PostgreSQL 与 HTTP 测试方式，覆盖保存后重读、普通用户禁止修改、匿名请求禁止访问等关键行为；测试只在 `fgas_test` 上运行。
- 沿用现有 MCP 契约与调用测试，覆盖 low/high 读取、管理员所属 low 仍不能写入、有效 high 保存并从网页读回同一内容，以及手册资源发现和 Schema 校验。
- 沿用现有迁移测试验证新增 revision；目录解析若存在可独立调用的生产逻辑，用简短用例覆盖子标题层级及重复标题定位。
- 前端运行 `npm run build`，最终运行 `git diff --check`。UI 按需仅截图检查桌面与手机布局，不自动点击或填写表单。
