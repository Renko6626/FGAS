# 首次记账确认本人资料

状态：用户已认可首次记账弹出配置、昵称辅助匹配、本人确认已有资料或创建新资料的产品方向；以下数据关联与接口方案待确认，尚未实施。

后续讨论已决定货物账户只维护一个负责人并允许变更、保留历史，详见同目录2026-10-27-stock-responsible-design.md。本文关于Member与货物账户的关联须沿用该统一负责人关系，不恢复联系人/保管人两套独立设置。

## 已确定的体验

- 注册/首次登录只建立登录用户，不自动创建联系人或账户。
- 未配置的用户点击“登记资金/资金转移”进入首次资金录入前，弹出本人资料确认；配置后继续原来的录入。关闭配置弹窗则结束本次打开录入的操作，不影响浏览。
- 配置只需做一次，不要求用户分别到联系人和账户页面完成多次手工设置。
- 昵称只推荐候选，不自动绑定、合并或认领。
- 此功能不修改账本余额、历史流水、审批角色或 low/high 权限。

## 数据关联与取舍

推荐增加 `User.member_id`：可空、唯一、外键指向 Member。一名登录用户可关联一个本人联系人，同一联系人只关联一名登录用户；未登录的联系人保持无用户关联。

账户继续沿用现有 FundAccount.member_id，不再增加账户到用户的第二份关联。联系人仍可有多个资金/货物账户，不强加“一个人只能一个账”的限制。首次配置需要至少一个关联资金私账；不创建货物账户。后续记账涉及哪个私账，继续由录入界面选择，不额外保存默认账户指针。

相比把 user_id 放到联系人上，User.member_id 方便现有登录响应和会话直接携带本人联系人ID，前端和MCP无需另查一层身份；两种方式均可表达一对一，本方案选前者。相比账户直接绑用户，复用现有联系人关系能避免两份账户归属关联并存。

需要新增 Alembic revision，不修改已应用的0001基线。已有用户初始 member_id=null，首次记账时同样进入确认步骤；不按姓名自动回填旧数据。

## 昵称候选

- 用当前 User.display_name 匹配 Member.name；也检查尚未关联联系人的现有资金私账名称，以减少遗漏旧独立账户后重复建账的情况。
- 使用标准库做轻量相似度排序：统一全半角、大小写及空白后，完全相同优先，再按 difflib.SequenceMatcher 相似度降序；同分以名称/ID稳定排序。默认展示最多5项，允许用户搜索其他资料。
- 无外部模型或匹配服务，无新增依赖；相似度仅为排序，不是身份验证，不显示“确认是本人”的概率。
- 展示候选姓名/账户名、联系人备注、关联资金私账，明确由本人选择；已绑定其他登录用户的联系人不可再认领。

## 两条本人确认路径

### 选择已有资料

1. 选已有联系人：建立 User.member_id；已有资金私账全部复用，无私账时确认创建一个零余额私账。
2. 选未关联联系人的已有私账：确认创建本人联系人，再把该私账的 member_id 指向新联系人，同时绑定 User.member_id；不移动金额，不再另建私账。
3. 既有账户若已指向联系人，使用其原联系人，不允许把它转给另一个联系人。保留账户启停状态；已停用的账户提示由有权限的人处理，不自行启用。

### 没有已有资料，为我创建

本人确认姓名后，一次创建联系人、一个名称为“姓名私账”的零余额资金私账，以及 User.member_id 关联。资金账户 kind=private，member_id 为新联系人ID；联系人只预填姓名，不复制SSO凭据或另建登录用户。

两条路径使用现有事务和写锁完成；不创建独立配置状态机、审批队列、自动重试或请求恢复。配置不授予普通用户通用目录维护权限，只允许完成上述本人初始化。

## 本人 HTTP 接口

- `GET /api/personal-account-setup?q=...`：人工Cookie会话，读取本人当前关联、已关联资金私账及推荐候选；不写入。响应含 configured、member、accounts、candidates。仅有关联联系人且有资金私账时 configured=true；账户停用另提示，不自动另开账。
- `POST /api/personal-account-setup`：人工Cookie会话，明确选择一种 mode：member / account / create；分别提交 member_id / account_id / name。用户ID始终取当前会话，不能由请求指定。返回配置后的本人关联和账户。
- 登录及 `/api/auth/me` 等既有用户视图增加 nullable member_id。
- 管理员可在既有用户管理接口/页面更正本人联系人关联；不新增另一套身份管理。角色等原有权限不变。

应用层负责本人配置、联系人/账户选择和权限，现有目录/持久层复用必要创建与读取；入口不直接写数据库。普通通用建联系人/账户接口继续原权限。

## 前端触发位置

复用 App.vue 集中 `create()` 入口；未配置时展示一个遵循现有Naive UI样式的确认弹窗，配置完成刷新本人身份与工作区，再打开TransferEditor。人工期初资金录入不强制配置个人往来资料。

不在登录后自动弹出，不影响浏览、审批、只读查询；本期不对所有后端资金写接口增加“必须先配本人资料”的全局限制，避免影响管理员代录他人账目。已有配置不重复推荐，不在每次资金提交时重新建资料。

## MCP

在已有 fgas_help 首次响应中补充 current_user 的 id/display_name/member_id。模型使用现有 fund_accounts 查询的 member_id 与 kind=private 过滤找到本人私账；不增加顶层工具、查询resource或新的账户归属字段。

本人配置仍走网页确认，MCP不提供昵称自动认领或low身份绑定写入。处理“我垫付了”时未关联，模型引导用户到网页点击登记资金完成一次配置；多人多账时不猜账户，不因此索取high。普通指定端点的Agent业务仍按既有权限办理。
