# 网页助手接入设计与原型边界

## 已确认

用户希望页面内提供 Agent 对话，支持个人 BYOK 和管理员提供的 DeepSeek 公共模型。用户创建时同步建立并启用一个属于本人的 low 网页助手连接。Agent 主循环在后端，采用 Pydantic AI 精简版，模型使用 DeepSeek 的 OpenAI 兼容 Chat Completions 协议；工具沿用 FGAS MCP 的授权与审计。

此前比较过前端主循环、后端主循环及混合方式，用户选择后端。框架比较过 Pydantic AI 与 LangChain，用户确认 Pydantic AI；当前 LangChain MCP 适配依赖 MCP 1，而 Pydantic AI 的 FastMCP 4 客户端支持本项目 MCP 2.3.0。

## 本轮可运行原型

- 在隔离分支增加 opt-in `FGAS_WEB_AGENT_PROTOTYPE=1`，默认关闭。沿用现有 FastAPI 和 Vue，不发布到生产、不修改现有数据库结构。
- 后端新增网页助手应用服务和 Cookie HTTP 入口。每次请求根据真实登录用户解析本人启用的 low 连接，并通过该连接的 Bearer 凭据调用本机 MCP；Cookie 不作为 MCP 凭据。
- 开启原型时，Casdoor 创建新用户后，同一事务调用既有连接应用服务创建启用的 low“网页助手”。已有用户可选择本人 low 连接，或通过原有连接管理功能创建。原型显式选择连接 ID；正式版稳定默认关联见下节。
- 模型在服务器端由每次请求选择个人 Key 或 `FGAS_DEEPSEEK_API_KEY`；官方 DeepSeek URL 固定，不开放任意 Base URL。公共模型默认 `deepseek-flash`，可在两个官方模型之间选择。
- 原型个人 Key、聊天历史和本次会话用量仅保存在当前页面内存，不进入 localStorage/数据库。后端接收文本历史，工具调用与工具结果只由本轮真实 MCP 执行产生。失效 Key 直接提示，用户可主动切换公共模型，不自动重跑业务操作。
- Pydantic AI 驱动 Agent 循环，流式返回文本、工具开始/结束、用量与结束事件。前端助手为根部常驻的悬浮组件，右下角可随时唤起；业务页面切换和收起不销毁会话及当前流。桌面面板加宽并缩减非聊天区，助手回复支持基本 Markdown（关闭 HTML/图片），FT/ST 采用页内跳转。模型设置为独立弹窗。用户手动打开、无可用配置尝试对话，或当前模型配置失败时弹出；未修改/确认的已知失败配置再次发送前仍会引导配置。模型错误与业务工具错误区分，不自动重发业务操作。界面显示费用来源、工具状态及 FT/ST 单据链接。
- 管理员可按需查询公共 DeepSeek 账户余额及刷新时间；原型不把当前浏览器的用量当成全站历史消费。
- 依赖放在单独的 `backend/requirements-agent.txt`，使用隔离虚拟环境验证；固定 Pydantic AI 2.63.0 与 FastMCP 客户端 4.1.4。不改动生产 Docker 构建路线。

## 正式接入计划中仍需确认的存储决定

1. 为用户与网页助手建立稳定的默认连接关联，保证改名、停用后仍能定位同一连接；不依靠显示名称猜测，不自动重建已停用连接。
2. 个人模型配置与加密 Key、会话和消息、调用用量记录的表/字段及保留范围；公共用量按用户/模型/日期聚合，供应商余额与本系统估算费用分别展示。
3. 所有新增结构使用新 Alembic revision，不能修改现有 0001 基线。已有用户的默认连接补齐随迁移方案一起确认。
4. high 网页连接、跨设备历史、长期后台运行、断线续跑另行决定；原型只沿用 low 的查询和待审批提议，不增加恢复机制。

## 验证边界

只允许在 fgas_test 运行数据库测试与本地原型联调。真实模型用量需要用户提供专用 Key 后才能验证；无 Key 时使用 Pydantic AI 的本地模型替身驱动真实 MCP，结果明确区分。前端类型检查/构建，页面最多截图，不做浏览器自动点击或填表。新永久测试只覆盖当前用户与连接绑定这一权限边界及新用户默认连接这一关键行为，不扩展 CI。
