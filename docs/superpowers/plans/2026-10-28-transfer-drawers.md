# 转移办理抽屉实施计划

**目标：** 按用户确认的方案统一资金和货物抽屉：核对信息前置、次要资料收起、底栏固定当前操作，货物完成在抽屉内填写日期和核对库存变化。

**技术与范围：** 沿用 Vue 3、Naive UI、既有 HTTP 接口和权限。只调整 `TransferDetail.vue`、`StockTransferDetail.vue` 及共用样式；将仅供货物抽屉使用的完成弹窗并回抽屉，移除不再使用的组件。不改数据模型、接口、后端、审批状态或库存生效时机，保留当前未提交改动。

- [x] 资金抽屉采用任务标题、紧凑摘要、默认折叠的分录和操作记录，拒绝／冲销原因与审批按钮放入 Naive UI 固定 footer。
- [x] 货物抽屉前置完整货物数量，保留待审批、待完成、完成报告待确认各自办理入口；日期及库存变化在同一抽屉核对，关联和追溯默认折叠。
- [x] 共用两页的布局样式，保留完整账户名称、单据编号、关闭／刷新／复制、错误和成功反馈；手机底栏可见。
- [x] 集中运行 `npm run build` 和 `git diff --check`；通过单据深链接截图核对桌面／手机及两档角色，不自动点击或填表，不执行业务写入，不新增永久测试或运行后端数据库测试。

**核对重点：** 资金批准仍使用版本号；货物批准不记库存，整笔完成才记库存；已有待确认报告不重复新建完成报告；普通用户只可报告完成；拒绝／取消／退回各自传递原因；请求进行中不能关闭或重复提交；结束单保留查看和原有更正入口。

## 实施结果

两个抽屉已统一为任务标题、核对摘要、默认收起的关联与历史、固定底栏。货物完成日期和逐项库存变化并入同一抽屉，移除不再使用的独立完成弹窗。各原因表单每次只办理当前选定动作；成功与错误反馈在底栏可见。

`npm run build`（TypeScript 与 Vite）和 `git diff --check` 通过，保留既有主包超过 500 kB 提示。以既有演示数据通过深链接截图核对资金待审／已过账、货物待审／待完成／报告待确认／已完成、普通用户及手机布局，主按钮均在视口内，默认无展开的次要资料或完成弹窗；无页面脚本或 API 错误。源码审阅未发现接口、权限、动作保留方面的阻断问题。未自动点击或填表，未执行审批、完成、关联、冲销等业务写入，未运行数据库测试。
