# 库存额外机制删减记录

用户已确认删除以下机制，适用场景为几个人低频记账。本次以减少功能、状态和数据库模型为目标；此前只抽取共用函数的实现已经退役。

| 删除内容 | 现在的处理 |
| --- | --- |
| useOperationAttempt、原请求缓存、冻结表单、冲突查询与人工解锁、跨表单互锁 | 提交期间 busy；失败显示错误，用户正常查询、刷新或重新操作。 |
| 库存完整请求回放、操作键和双版本 | 基于数据库当前状态执行；事务、串行锁和正式流水唯一约束保留。 |
| StockOperation 回放模型、外层操作键、子键碰撞检查、额外保存点 | 钱货在已有 HTTP 事务中创建；资金仍按原接口处理自身操作键。 |
| StockDifference/StockDifferenceAdjustment、差异状态和有效调整管理 | 盈亏直接建普通 Transfer，related_transfer_id 指向原已完成转移。 |
| 专门验证回放、子键碰撞和差异管理的测试 | 删除不再适用的用例；其余已有核心测试随现行接口迁移。 |

保留：仓库、整数 SKU、多 SKU 转移、批准后在途、手动整笔完成、普通用户完成二次审批、保管历史、库存查询、资金关联、基本权限、正整数与负库存校验、整笔事务及业务唯一约束。本次不改变资金和垫付已交付的机制。

旧 schema 使用显式兼容命令添加并回填原单关联、解除弃用字段的写入要求。旧表与字段历史保留，活动模型不再引用；新建 schema 不包含退役模型。没有清空开发数据或自动迁移。精确命令见 [README](../README.md#stock-transfers-and-quantity-inventory)。

网络失败先人工查询；两条独立记录重复时按依据更正，不再为此增加恢复系统。全仓盘点、复杂历史更正、自动补偿和云端全功能验收均不在本次范围。实际检查结果见 [阶段记录](prototype-status.md)。
