# 货物操作表单的局部简化

使用场景是几个人低频记账。本次只整理完成、差异登记和转移详情三处前端请求处理，遵循 [现有架构的实现边界](../architecture.md#14-当前实现边界2026-10-13)：权限、审批、事实写入、事务和幂等仍由原后端负责，前端只保存一次操作尝试并提示用户核对结果。

| 特性 | 本次处理 |
| --- | --- |
| 原请求、版本和幂等键快照 | 共用 `useOperationAttempt` 在首次提交前复制 JSON 请求；后续重试使用完整原请求。 |
| 防重复点击、未决请求、卸载保护 | 共用 busy/pending 和组件卸载检查；每个组件只保留一个尝试。 |
| 400/422 输入错误 | 共用释放逻辑，保留表单内容供修正。 |
| 明确未提交的 409 冲突 | 页面注入现有错误分类；共用读取当前记录、显式确认结束失败尝试。读取失败不释放原请求。 |
| 网络错误、5xx 或未知 409 | 保留原键重试，不自动生成新请求，也不要求再次交货。 |
| 成功及核对后的刷新 | 页面提供执行、查询、当前记录更新和成功回调；共用函数不认识货物类型、路径或权限。 |

删除了三个页面各自的请求缓存、重复 busy/error/conflict 状态处理、失败分类、查询与确认释放代码，以及重复的卸载标记。转移详情的 `retrying` 也由共用的 pending 派生，避免维护两套未决标记。提交后的刷新不再落入“写入失败”的处理分支。

仍由业务页面负责：整数观察值与零/留空的区别、请求路径及键生成、批准范围快照、来源/目标和差异符号、审批权限、父子表单互斥、当前记录展示，以及详情查询迟返回的防覆盖检查。它们没有抽成额外通用层。

这些恢复功能都能共用，因而没有额外删除业务功能。没有全局队列、通用工作流、自动补偿、持久化草稿或新依赖；资金表单本次不迁移。整页重载和身份切换仍清除内存尝试，结果不确定时由既有查询与原键重试核对。

验证范围是迁移完成后一次 `frontend` 的 `npm run build` 和 `git diff --check`；不启动服务，不执行浏览器交互、数据库或后端测试，不新增永久测试。
