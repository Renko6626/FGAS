# MCP 客户端接入阶段记录

记录日期：2026-10-27。实验针对本机开发服务和专用 `fgas_test`，不代表远程 HTTPS 或生产验收。接入说明以[公开指南](../../frontend/public/agent-setup.md)为准。

## 已确认的使用方式

成员按需创建个人 low 连接，连接属于真实用户；管理员才可创建 high。用户可再次查看自己的密钥，并按社团内部约定直接粘贴到对话，让 Agent 写入本机 MCP 认证配置。无需先准备环境变量。low 写申请沿用统一人工审批，记录真实用户和连接来源。

## 客户端实验的区别

| 场景 | 观察与结论 |
| --- | --- |
| Codex 中的 Luna，用户粘贴密钥 | 使用 CLI 临时配置接入原生 MCP 并完成试记账。沿用已有模型登录环境；本地工具审批与 FGAS low/high 是两套权限。不要为了添加连接新建空 `CODEX_HOME`，也不要把模型服务的 401 当成 FGAS 密钥错误。 |
| DSH SDK／标准模式试验 | 首次配置阶段缺少 `plugin_manager`，出现反复查找安装入口；部分试验由父代理安装配置或重启后才完成业务。只能证明该入口受限，不能据此判断普通创造模式不支持自助接入。 |
| 官方 DSH Web 创造模式，直接 CLI 启动 | 用户只提供站点地址，随后回答密钥问题并允许一次安装。模型独立生成配置包、安装并在同一会话使用原生 MCP，完成待审申请和读回。该路径已跑通。 |

DSH 本机已统一到 `0.2.1-rc.3`。运行时升级和本机桥接工具适配属于本机环境，不是 FGAS 仓库的依赖变更；最后一次直接实验没有使用桥接工具、subagent SDK 或第三方插件管理器。

## 官方 DSH 创造模式直接实验

通过脚本直接运行官方 `dsh <独立 profile> --from-default-profile web --no-open --host 127.0.0.1 --port 0`，使用随附 Web profile 创建普通 `cordis` 会话和空工作目录。脚本通过正常 Web HTTP/WebSocket 接口提交消息、回答原生问题和安装许可；不向模型注入 MCP 运行时，不替模型写配置或发送业务调用。

1. 初始只提供 FGAS 地址及试记账任务，模型自行发现网页中的指南。
2. 模型通过原生 `ask_user_question` 索要密钥，脚本模拟用户粘贴个人 low 密钥。
3. 模型读取客户端指导，生成仅含配置的 bundle，使用官方 `@deepseek-ai/dsh-mcp-client`，调用 `plugin_manager` 的 `install_bundle`。
4. 脚本模拟用户对这一次安装选择 `allowed-once`。安装返回 `application: applied`，`mcp__fgas__*` 随即出现在当前会话，无需切换模式或重启。
5. 模型调用帮助、查询和提案，提交并读回一笔 0.01 元待审批资金转移。

首个脚本尝试把 Web 事件回复的 outcome 写成 `return`，被网关拒绝；当时尚未接受密钥，也未安装或提交业务。修正为 `result` 后，从新的空会话重新完成上述实验。这是测试脚本问题，不计作 DSH 接入失败。

实验结束已停止直接启动的 DSH Web 实例。私有配置包、密钥、启动令牌和会话日志不提交仓库。本机原始证据位于 `/tmp/sunyunbo/fgas-direct-web-K1uYoX/accepted.json`，控制脚本位于忽略提交的 `.superpowers/personal-agent-connections/dsh-web-coldstart.mjs`；临时路径可能被清理，主要方法与结果已保存在本记录中。

## 当前结论与边界

DSH 创造模式可作为首次自助配置入口。用户仍需提供密钥、批准安装；完成配置后可使用标准模式办理业务。没有安装工具时，指南应立即指出所缺能力并引导启用 MCP，避免反复扫描客户端内部实现或手写协议客户端。

当前证据覆盖一次本机普通 Web 创造模式冷启动及一笔 low 资金申请，未验证远程 HTTPS、多平台客户端、所有 DSH 模式或完整货物业务。没有因此新增 FGAS 协议、数据库机制或客户端专用后端。
